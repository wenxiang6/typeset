## P0 · 数据安全（强烈建议优先）

### 1. 多个窗口 / 标签页会互相覆盖存档 ⚠️ 最危险
- **现象**：存档只有 `localStorage`，全局**没有监听 `storage` 事件**、没有 `BroadcastChannel`、没有单标签锁。同时开两个窗口（或网页版 + 桌面版），两边都按 400ms 写同一个 key，后写的静默盖掉先写的；10 秒快照也是共享同一份 list，一个窗口会把另一个窗口的时间线冲掉。
- **影响**：符合"防止意外导致内容丢失"的原始诉求——这正好是最容易踩的那种丢内容方式，而且完全静默，没有任何提示。
- **建议**：
  1. 监听 `window.addEventListener('storage')`，检测到外部写入就弹（新的）Notice：「检测到另一个窗口修改了这份版面」→ 提供「重新加载 / 保留当前」两个选择；
  2. 或者更简单：加一个 `BroadcastChannel` 心跳，第二个窗口进来时直接只读 + 提示。
- **涉及**：`src/editor/store.ts:139`（自动保存 effect）、`src/editor/autosave.ts`

### 2. 图片 base64 直接塞进 localStorage，迟早撑爆配额
- **现象**：「选择本地图片」走 `FileReader.readAsDataURL`，整张图（未压缩）变成 data URL 写进 `el.src`，再随 `JSON.stringify(doc)` 进 localStorage。一张 2MB 照片 ≈ 2.7M 字符 ≈ 配额的一半。
- **现有兜底**：`autosave.ts` 写不进去时会先 `clearSnapshots()` 再试（保主存档逻辑是对的）；失败时工具栏红点 + 提示。
- **缺口**：① 用户不知道"我插了 3 张图之后快照历史就没了"；② 主存档也可能写不进去，界面只有一个红点，**没有强制引导导出**；③ 每次 `doc` 变动都要 `JSON.stringify` 一遍含几 MB base64 的字符串，编辑会有卡顿。
- **建议**：
  1. 插入时降采样（限制最长边 ≤ 1600px）+ 转 JPEG 质量 0.82，通常能压到 1/10；
  2. 存新字段 `srcAsset`（二进制/外部引用）与 `src`（展示用）分离；
  3. 算一下 `doc` 体积，> 2MB 时在存档按钮里给黄色预警 + 一键「导出到磁盘」。
- **涉及**：`src/editor/Inspector.tsx:673`（图片 base64）、`src/editor/autosave.ts:171`

### 3. Windows 上填本地图片路径必定失败
- **现象**：`localImage.ts` 的绝对路径判断只认类 Unix：
  ```ts
  if (/^\/(Users|home|Volumes)\//.test(s)) { … }
  ```
  Windows 的 `C:\Users\foo\a.png`、`D:/素材/图.png` 全部落到 `return s`，`<img src="C:\Users\...">` 被解析成相对 URL → 破图。
  `isLocalPath()` 同样只认这两种。
- **影响**：刚打好的 Win 版给用户，按 UNC/盘符路径插图一定失败，而且**报错看不出来**（只是图片位空白）。
- **建议**：补盘符与反斜杠解析 `/^[A-Za-z]:[\\/]/`，统一归一成 `file:///C:/...`；桌面版直接走 `/@local` 代理。
- **涉及**：`src/editor/localImage.ts:33`、`src/editor/localImage.ts:51`

### 4. 单文件版（双击 HTML）的「Word」按钮必然失败，但入口没拦
- **现象**：`dist/地理周刊-排版编辑器.html` 没有 `/@doc-import` 服务，点 Word 会走 `Failed to fetch`，弹出蓝色错误 Notice。文案里有一句补救说明，但用户是先点错才看到。
- **建议**：运行时探测 `fetch('/@doc-import', {method:'HEAD'})` 或用 `location.protocol === 'file:'`，在 file:// 下把 Word 按钮**置灰 + tooltip 写明「桌面版 / pnpm dev 才能用」**。同理可用于预览里的其它依赖 http 的能力。
- **涉及**：`src/editor/Toolbar.tsx:352`

### 5. 导入外部 JSON 时 HTML 未净化
- **现象**：导入版面 JSON / `.paiban.json` 模板后，`el.html` 直接进 `dangerouslySetInnerHTML`（`Canvas.tsx:146`）。现在只导入自己导出的文件，风险为零；但模板库本来就是"分享给别人导入"的设计。
- **建议**：加一层轻量白名单净化（标签 / `style` 属性白名单、剥 `<script>`、`on*`、`javascript:` URL）。几十行就能做。
- **涉及**：`src/editor/Canvas.tsx:146`、`src/editor/templates.ts:83`

## P1 · 高频痛点

### 6. 原生 `confirm` 残留 3 处，和玻璃态 UI 完全不搭
| 位置 | 内容 |
| --- | --- |
| `Inspector.tsx:109` | 删除当前页 |
| `Inspector.tsx:134` | 重建分页 / 修复空白页 |
| `TemplateDialog.tsx:71` | 删除模板 |

工具栏那批已经换成 `Notice.tsx` 了，这三处漏了。原生框在 Electron 沙箱窗口里样式突兀，也不支持 Esc/聚焦回归。
→ 统一换成 `<Notice>`，`Inspector` 需要把它提升到组件里或抽出一个 `confirmNotice()` 命令式 helper。

### 7. 组件级「剪切 / 复制 / 粘贴」缺失
现在只有 `Ctrl+D`（原地偏移 16px 复制），**没有跨页/跨栏粘贴**。要把一个做好的组件搬到第 3 页同位置，得先搬到目标页再手挪。
→ 加内部剪贴板（`{el}` 序列化，含 style/sub），`Ctrl+C / Ctrl+X / Ctrl+V`（在鼠标位置或原位置 +16px 粘贴）。

### 8. 不能多选
`drawMode` 的框选只生成**区域辅助框**（`Canvas.tsx:631 startBand`），不产生选区。想同时移动 5 个组件只能一个一个来，也无法同时对多个组件改字号/颜色/对齐。
→ 加 `Shift+点击` 多选 / 空白拖框多选，配合第 9 项。

### 9. 没有对齐工具
左对齐 / 居中 / 右对齐 / 顶对齐 / 垂直居中 / 底对齐 / 等间距分布——一个都没有。现在只能靠 `Num` 手填 X/Y 和网格吸附。这是排版工具里每天用几十次的东西。

### 10. 没有图层面板，重叠组件选不中
只有属性面板里的置顶/上移/下移/置底（`Inspector.tsx:923`）。被完全遮住的组件**在画布上点不到**，只能靠 Z 键逐步调整去找。
→ 右侧加一个「图层」标签页，列出当前页组件（显示 `componentName` + 可见/锁定），支持点击选中、拖拽调序、隐藏。

### 11. 图片只能点按钮或填路径
不支持：拖图片文件到画布、从剪贴板 Ctrl+V 粘贴截图。做周刊时大量图片是截图/微信收来的，这一步差别很大。
→ 在 `PageView` 的 `onDrop` 里判断 `dataTransfer.files`，有图片就在落点建 image 组件；同时接 `paste` 事件的 `clipboardData.items`。

### 12. 没有全局搜索 / 替换
几十上百个组件里找不到某段文字在哪里，也没有"把这个词全刊替换"。
→ 左侧搜索框升级成全文搜索，命中列表点一下跳转选中。

### 13. 撤销历史不可视
现在只有 `past` 栈（上限 60）+ 10 秒快照，都是线性的、看不见。误操作后用户不知道"我到底还能退到哪一步"。
→ 存档浮层里再加一栏「操作历史」，显示最近 N 步 + 发生时间，点击跳回去（`past` 已有数据，主要工作量在 UI 与"跳到中间某步"的状态处理）。

### 14. 没有快捷键总览 / 帮助面板
快捷键已经不少（Ctrl+Z/Y/D、Delete、Esc、方向键交换、Alt+方向键微调、Shift×10、Ctrl+滚轮缩放…），但**只能靠 hover tooltip 一个个发现**，`?` 或 `Ctrl+/` 没有任何反应。
→ 一个快捷键速查浮层，成本极低、收益很高。

## P2 · 打印与桌面版

### 15. 打印预览不记忆上次的「彩色 / 黑白」
`print.ts` 的 `bw` 参数每次调用都传 `false`。用户习惯打黑白的话每次都要点一下。
→ 存 `localStorage`（`paiban-print-bw-v1`），读出来作为默认值。

### 16. 没有「导出 PDF」一键入口
现在只有「打印 / 保存 PDF」→ 系统面板 → 手动选「另存为 PDF」。三步且依赖系统。
→ Electron 主进程的 `webContents.printToPDF()` 可以直接落盘，加一个「导出 PDF」按钮即可（网页版回落到现在的行为）。

### 17. 桌面版不记忆窗口大小 / 位置 / 侧栏折叠
每次启动都是固定的 1500×950 居中。
→ `main.cjs` 里用 `win.getBounds()` + `electron-store` 或自己写个 JSON 到 `userData`（不想加依赖就自己写，十几行）。

### 18. 桌面版没有更新通道
三个包都是手动分发，用户不知道有新版本。
→ 至少加一个「检查更新」菜单项打 GitHub Releases 或内网目录；或有精力上 `electron-updater`。

### 19. 关闭窗口时没有"未保存"兜底确认
实际上 400ms 已经落盘、`pagehide` 还会补写一次，风险很低。但 `beforeunload` **不会因为存储失败而拦截**——如果处于配额爆掉的状态，关窗就真丢了。
→ 保存状态为 `ok: false` 时挂 `beforeunload` 提示。

## P3 · 文案与一致性

### 20. Inspector 的方向键说明已经过时（与实际行为矛盾）
- 实际：方向键 = **与相邻组件交换**；`Alt+方向键` 才是 1px 微调（`Editor.tsx:159`）。
- 但 `Inspector.tsx:943` 仍写着「方向键 1px 微调，Shift + 方向键 10px」。
- 画布提示条（`Canvas.tsx:869`）和 README 是对的，只有属性面板是旧的。
→ 改一句文案；建议这句话做成唯一来源常量，避免再次漂移。

### 21. 没有"未保存改动"脏标记
只有「上次保存 19:07:12」。用户分不清"已经存了"还是"还没存"。
→ 有未落盘改动时就把「上次保存」换成小圆点 +「编辑中」，`raw !== lastWritten` 时点亮——数据已经在 `store.ts:118 lastWrittenRef` 里了，改起来很便宜。

### 22. 保存失败时太安静
红点 + tooltip 里的红字，用户基本看不见。配额满这种事需要**主动弹一次** Notice（只弹一次，别每次都弹）。
→ `autosave.publish` 在 `ok` 由 true→false 时触发一次全局提示。

### 24. 页面列表 `key={i}`
`Canvas.tsx:874` `<PageView key={i}>`。删除中间某页时，下方所有页的 React 组件会被重建（虽然 PageView 内部状态不多，但編輯中的 DOM、测量中的高度都会丢）。
→ 改成 `key={p.id}`，一行动。

### 25. keydown effect 每次渲染都解绑重绑
`Editor.tsx:192` 依赖 `[api]`，而 `useEditor` 的返回值是 `useMemo` 出的**全新对象**（每次渲染都变），所以每次渲染都会 remove/add 一遍全局 keydown。
→ 依赖改成 `[apiRef]`，内部从 `apiRef.current` 取；或对 `useMemo` 的返回值做稳定化。

### 26. 测试链路依赖外部环境
`pnpm smoke` 要 90 秒且依赖 dev server，`tools/import/verify.mjs` 依赖一份真实的 `.doc`。目前跑得很好，但 README 里没有写"要在什么前置条件下跑 xxx"，新环境接手会卡住。
→ 补一节「本地如何跑测试：前置条件 + 期望耗时 + 失败时先做什么」。

### 27. 无障碍（a11y）
组件只有 `data-el-id`，没有 `role` / `aria-label` / 键盘 Tab 焦点。屏幕阅读器完全不可用，键盘也无法脱离鼠标选中组件。
→ 至少给选中态加 `aria-selected`、给画布加键盘游走（Tab 在组件间移动）。

### 28. 没有暗色模式
UI 写死浅色，且 `package.json` 里 `mac.darkModeSupport: false`。晚上排版刺眼。
→ UI 色值抽成 CSS 变量 + `prefers-color-scheme`，工作量主要在 CSS。

### 29. 表格没有合并 / 拆分单元格
只有「＋行 ＋列 −行 −列」和拖拽调宽高（`Inspector.tsx:547`）。做试卷那种带合并表头的表格做不到。
→ 在 `table.ts` 的 model 里加 `span` 支持。
