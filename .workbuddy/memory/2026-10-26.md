关键实现经验（踩过的坑）：
1. **测量容器必须带 `.ed-page` class**。字体族/字号/行高都定义在 `.ed-page` 上，
   挂在 body 下量出来的高度偏矮（行高不同），会导致装箱溢出、阅读顺序被引擎打乱。
2. **reflowDoc 的第 1 页规则是「左右栏溢出都进第 2 页左栏」**（README 有写）。
   所以装箱必须保证每栏不溢出，否则左栏尾部会排到右栏内容之后 → 乱序。装箱留 10px 余量。
3. 图片高度必须等于 `colW / ratio`（比例为真的话约 284px，受 `.img-ph img` 的 287 上限约束），
   不能随意压低，否则图片溢出框压到下方元素。
4. 图片抽取结果：`Data` 流里是 5669×945 校徽 logo，**配图 1200×669 在 `WordDocument` 流**，
   两条流都要扫。宽高比 < 4 的第一张当正文插图。
5. `textutil` 的 p 字号是层级信号：16px=一级标题、15px=二级标题、11px=正文；
   光靠 `<b>` 分不出标题层级。

验证结果（`~/Desktop/docs/地理时政周刊一.doc`）：
- 112 段 → 66 个组件，解析耗时约 140ms；变体：section-title 8 / subhead 14 / concept 3 /
  chain 2 / trap 4 / tpl 2 / quiz 3 / note 2 / req 3 / name-row 1 / image 1
- 版面不变量全 0：超出边界、重叠、溢出页底、页眉页脚重叠、内容溢出框
- 页数 4（成品 3）。原因：原稿内容量 + 自动间距 4px，第 4 页只有 3 行。
  已确认无法靠调图片高度压回（会破坏图片比例），属内容量差异，交给用户微调。
- `pnpm smoke` 32/32 通过（第一次偶发在模板库用例超时，重跑通过，与本次改动无关）

## 新增：短条目「合并/拆分」开关 + 末页孤行修复

用户诉求：把「学习要求 3 条」这类短条目做成可配开关，从规则层解决尾页孤行。

根因排查（重要，推翻了上一轮「内容量决定、无法回到 3 页」的结论）：
- 旧实现 packPages 每元素 +2px 测量余量、页底再留 10px 安全余量 → 每栏浪费 20~40px。
- 首期原稿的孤行是「差 0.2px」：第 3 页左栏剩 150px，下一个元素 146px+4px 间距，正好压线被挤到右栏，
  连锁把「本期学习要求」的 3 条推到第 4 页。**收紧余量后 3 页即可装下**，与成品 PDF 页数一致。
- 教训：`reflowDoc` 只做「溢出→推到下一栏/页」，**永远不会把元素拉回上面的空隙**，
  所以装箱时保守浪费的空间是不可逆的。装箱尺度比"合并"更影响页数。

实现（三层）：
1. `tools/import/rules.mjs`
   - 常量 `MERGE_VARIANTS=['req','circle','trap']` / `MERGE_MAX_CHARS=52` / `MERGE_MAX_ITEMS=6` /
     `MERGE_HEADING`（本期学习要求|必考能力|易错提醒…）。
   - `mergeShortRuns()`：连续的同类短条目合成一个组件，**并把紧邻上方的同类小标题一起带走**
     （避免标题留在上一栏底、列表跑到下一页）；合并只做同层 HTML 拼接，`parts` 保留原始分片，
     所以合并/拆分可无损互换，观感完全一致（只少 4px 间距）。
   - 每个组打 `grp` 编号：合并态带 `parts`，拆分态每个分片仍带同一个 `grp`。
2. `src/editor/importDoc.ts`
   - `importToDoc(payload, {merge:'auto'|'merge'|'split'})`。
   - `shapeElements(raw, pick)`：'all' / 'none' / Set<grp> 三种形态，靠 `parts` 与 `grp` 双向转换。
   - 两种装栏尺度 `PROFILES = {loose:{pad:2,slack:10}, tight:{pad:0,slack:1}}`，各排一遍取优。
   - 选优规则：页数最少 → 末页填充率更高（先淘汰孤行）。auto 额外逻辑：合并能省页就用合并；
     否则保留拆分的细粒度，只把**被分页切断的组**（元素 id 里带阅读序号 `imp-<idx>-`，据此反查页）合并后重排一次，
     页数不增加才采用。
3. `src/editor/Toolbar.tsx` + `editor.css`：Word 按钮改成浮层（`.ed-word-pop`），
   内含「选择文件并导入」+ 短条目 自动/合并/拆分 三选一，选择存 `localStorage: paiban-import-merge-v1`。

顺带修掉两个真 bug：
- **导入图片在版面里显示破图**：根因不是"截图太早"，而是 Vite 静态中间件对新写入文件**首次请求走 SPA 兜底**，
  返回 200 + 1886 字节 index.html → `<img>` 解码失败（`naturalWidth=0`，`decode()` 报 EncodingError）。
  实测同一 URL 50ms 后再请求就正常，重新赋 src 也能加载。修法：新增 `GET /@imported/<name>`
  自读盘中间件（`SAFE_NAME` 白名单防穿越），图片 URL 前缀随之改为 `/@imported/`。
- `verify.mjs` 截图前不图片等待 → 补 `waitImages()`（已提取到 `tools/browser-utils.mjs` 供复用）。

实测（首期原稿，三种模式都试过）：

## 改：拖动改为「停 1.5s 才挤开其他组件」

用户反馈：一拖就把别的组件顶飞。根因是 `Canvas` 的 pointermove 里每一帧都调
`resolveMove` 并把返回的 `pushed` 立刻应用，而 `resolveMove` 的级联本身不稳定（见下）。

改动（`src/editor/Canvas.tsx`）：
- `DWELL_MS=1500` / `DWELL_TOL=3px` 常量提到模块顶部。
- `move` 里只把 `res.rect` 应用到被拖组件，推挤结果存进 `pending`，不立即应用。
- 停稳 1.5s → `applyPush()` 应用；指针再移动超过 3px → `undoPush()` 用 `pristine` 还原，重新计时。
- 松手时再 `applyPush()` 一次落定，避免留下重叠（`endTx` 还会跑 `reflowDoc` 压缩）。
- 停住期间组件显示 **蓝色虚线框**（`.ed-el.is-dragging.is-awaiting-push`）提示"再等就位"。

**新发现的引擎坑（重要）**：`resolveMove` 的 pushed 级联会互相反复推，最后把若干元素一起堆到页底
（实测 p0-11/p0-12 双双被推到 y=727、互相重叠）。原因是 `pushOut` 的候选方向只有
`[preferred(下), natural, 右, 左]`，**没有 up**，加上 BFS 队列里后处理的元素会用已推移的位置再推别人，
结果越推越靠下。所以预览不能直接用 `res.pushed`。
→ 在 Canvas 里自己写了 `planPush(rect)`：同栏内按 y 排序，从被拖组件底边 +4px 起单调向下顺推，
锁定元素不移动但占用游标。结果与松手后 `compactPage` 的行为一致，且不会堆叠。
（`resolveMove` 本身没改，避免动到 Inspector 与既有冒烟用例。）

**另一个顺带修的坑**：`is-dragging` / `is-ghosted` 之前是 `classList.add()` 命令式加的，
但 `.ed-el` 的 className 由 React 计算，`setSelection` 触发的重渲染会把它冲掉 —— 所以拖动中的
橙色描边其实一直没生效。现在改成 `useState`（`dragging` / `pushHint` / `ghosted`）参与 className。

视觉：`.ed-el.is-dragging` 加了 97% 白底 + 阴影，拖动中浮在内容之上，压住的文字不会看成乱码；
`.is-dragging.is-awaiting-push` 用蓝色虚线表示"停够 1.5s 就让位"。

验证：拖动中其它元素 0 变动；1.2s 不触发、1.7s 触发；慢速连续拖（每 90ms 2px）不误触发；
让位后继续移动可 100% 还原（其它元素回到原始 y）；松手后 3 页、重叠/出界/溢底/页眉页脚重叠 全 0。
`pnpm typecheck` 通过。

**后续（用户觉得 1.5s 太长）**：`DWELL_MS` 改为 **800ms**。复测：停 600ms 被挤元素 0 个、
停 900ms 触发 9 个元素顺推；慢速连续拖仍不误触发；让位→回退→再让位循环正常。
改时长只需动这一个常量（`src/editor/Canvas.tsx` 顶部），CSS 与 README 的文案同步更新。

- 打印时 `@media print` 复位 `zoom:1`、隐藏 head/foot、`height:auto`，只输出纸张。

**踩坑**：
1. flex 列布局里 `.pv-body` 必须 `min-height: 0`，否则不收缩、底栏被顶出可视区（第一版就少了底栏）。
2. `body { height:100% }` 要配合 `html { height:100% }`；原来沿用旧代码的 `html,body { height:auto !important }`
   会让 `height:100%` 失效，body 永远不滚动。
3. `!important` 的作者样式能压过内联 `style.zoom`，所以打印复位用 `@media print { .pv-pages { zoom: 1 !important } }` 有效。

回归：`scripts/smoke.mjs` 里「预览纸张尺寸」断言从 `getBoundingClientRect()` 改成 `offsetWidth/offsetHeight`
—— 因为现在会按整页缩放，rect 是缩放后的值，offset 才是真实的 A4 布局尺寸（1123×794）。
实测同一份 HTML 顶层打印：3 页、MediaBox 841.9×595pt（A4 横），无空白页。`pnpm smoke 32/32` 通过。

## 改：分页阅读顺序统一为「左栏 → 同页右栏 → 下一页左栏」（第 1 页不再是特例）

用户需求：横版一页左右两块，左栏溢出应去**本页右栏**，右栏溢出才去**下一页左栏**。

根因：`layout.ts` 的 `reflowDoc` 里第 1 页有一段历史特例——左右栏**任一**溢出都直接
`insertAtTopInColumn(doc, i + 1, ..., 0)`，即整块跳进第 2 页左栏。原假设是「第 1 页两栏
都是设计好的固定内容」，对导入的长文完全错误：左栏变长时右栏还空着内容就跳页，阅读顺序也倒错。
（`i !== 0` 的分支本来就是正确逻辑。）

改动：删掉 `i === 0` 特例，所有页统一先 `findColumnOverflow(0)` → `insertAtTopInColumn(i, 1)`，
再 `findColumnOverflow(1)` → `ensurePage(i+1)` + `insertAtTopInColumn(i+1, 0)`。

验证：
- 首页左栏塞 400px 固定高图 → 落在**第 1 页右栏**（旧行为是第 2 页左栏）。
- 90 段合成稿导入：4 页，每页左底=右底（681/691/691），末页左满右不满；90 个元素的阅读顺序
  按 (页,栏,y) 排列**严格单调递增**。
- 真实原稿 `地理时政周刊一.doc` 导入仍 3 页，分栏结果与改动前一致（本来首页没溢出）。
- `pnpm typecheck` 通过；`pnpm smoke` 32/32；新增一条用例
  「左栏溢出：先流到本页右栏（第 1 页也适用）」（`scripts/smoke.mjs`，截图 `03a-left-column-flow.png`）。

README 的「阅读顺序」小节同步改写。

## 改：家具可选中/可双击编辑、内部元素竖排、文字框自动长高

用户三点反馈，对应根因与改法：

**1. 第一页标头/页眉/页脚不能双击选中**
根因：`importDoc.ts` 给 `header / masthead / footer` 都设了 `locked: true`（初始模板没锁），
而 `Canvas.startDrag` 第一行 `if (el.locked || editing) return` 连 `setSelection` 都没走到，
所以点上去完全没反应；`onDoubleClick` 也排除了 `el.locked`。
改：`startDrag` 对 locked 只做 `setSelection`（不进入拖拽事务）；`onDoubleClick` 去掉 locked 限制。
→ 锁定只禁止拖动/改尺寸，选中、改样式、双击改文字都正常。
同步把 Inspector 里锁定件的说明文案改成真实行为，并**禁用** X/Y/宽/高 与三个搬页按钮
（`Num` 增加 `disabled` 属性），避免锁定件被搬到别的页。

**2. 右侧「内部元素」要竖排**
`.ed-sub-list` 从 `grid-template-columns: 1fr 1fr` 改为 `flex column`，一行一个、占满宽度，
`max-height: 168px` 超出滚动。

**3. 文字框装不下要拉高**
原本自动高度已能跟随宽度变化，但两个缺口：
- `autoHeight === false`（拖过高度手柄 / 属性面板输入过「高」）的元素被完全跳过 → 内容溢出框外压住下文。
  改为：`applyHeights(doc, heights, { growLocked: true })`，锁高元素**只在内容更高时向上长、绝不缩回**；
  `store.applyMeasuredHeights` 同步放宽判断。Canvas 测量侧对 locked 元素也收集 `natural > h + 1`。
- 编辑输入过程中 `editingId` 会阻断测量，只有退出编辑才变高。
  改为 `ed-live` 的 `onInput` 直接写 DOM 高度（不写文档，避免重建 contentEditable 丢光标）。

验证：锁高 h=20 + 窄宽 → 自动长到 65；锁高 h=300 → 保持 300 不被缩回；编辑中输入 → 框 65→239 实时跟随。
导入后三件家具单击全部能选中、报头双击能进编辑、拖动 y 不变。

## 新功能：方向键与相邻组件交换位置

用户需求：选中组件后，用方向键与上下左右相邻的组件交换位置（比拖来拖去方便）。

**键位取舍（重要）**：方向键原本是 1px 微调（Shift = 10px）。改为
- **裸方向键 = 交换**（用户明确要求）
- **Alt / Option + 方向键 = 微调 1px**，再加 Shift = 10px
- 选中复合组件的**内部元素**时，方向键仍只微调内部元素（不走交换）

实现：
- `layout.ts` 新增 `SwapDir`、`findNeighbor(doc, pageIdx, id, dir)`、`swapWithNeighbor(...)`。
  - 邻居判定：垂直方向要求 x 投影重叠 ≥ 30%，`↑` 取 bottom 最近且 `e.y+e.h <= cur.y+2`；
    水平方向要求 y 投影重叠 ≥ 30%，`→` 取 left 最近且 `e.x >= cur.x+cur.w-2`。
    排除 furniture / 背景 / region / 锁定件。
  - **只交换阅读顺序，不改两者合计占用空间**：`↑` 时 cur 落到 other.y，other 落到
    `other.y + cur.h + 原间距`，所以总底边不变，不会下压其他内容，也不需要 reflow。
  - 水平交换宽度不同时，若交换后越出版心则放弃（返回 null）。
- `store.ts` `swapNeighbor(id, dir)`：先 `findNeighbor` 探测，没有邻居直接返回 false（**不写撤销历史**）。
- `Editor.tsx` 键位重写；`Canvas.tsx` 画布提示文案更新。

验证：同栏 p0-18(h43)↑ 与 p0-17(subhead,h21) 交换 → 43 高的到 648、21 高的到 695，
原底边 716 保持不变；再按 ↓ 完全还原。跨栏 → 从左栏 x=45 换到右栏 x=568。
Alt+↓ 精确移动 1px；无邻居时历史长度不变（1→1）；不变量全 0。

## 20. 打包成桌面应用（Electron → dmg / Windows 免安装 zip）

- **架构**：`electron/main.cjs`（CJS 主进程，起窗口）+ `electron/server.mjs`（node:http，
  127.0.0.1 随机端口：dist 静态 + `/@doc-import` + `/@imported` + `/@local`）+ `electron/preload.cjs`
  （contextBridge 只转发「菜单打印/打开 JSON」）。窗口加载 http 而不是 file://，
  因为 `fetch('/@doc-import')` 和本地图片代理都需要 http 源。
- **server-plugin.mjs 重构成可复用**：`handleImport(req,res,{imagesDir,tmpDir})`、
  `serveImage(req,res,imagesDir)` 导出；vite 插件只是把 public/images/imported 传进去。
  桌面版把 imagesDir 指到 `userData/imported`（asar 只读）。
- **跨平台 Word 转换**（`tools/import/parse.mjs`）：darwin textutil → 全局 chain：
  soffice → Word COM → WPS COM（PowerShell `SaveAs2(...,8)`），HTML 用 TextDecoder 按
  meta charset 解码（Win 中文常是 gb2312）。删掉了原来「非 darwin 直接 501」的硬门。
- **图标**：`scripts/make-icon.mjs` 纯 Node 逐像素画 + 手写 PNG（zlib），
  electron-builder 自动转 icns/ico。
- **签名**：`scripts/sign-adhoc.cjs`（afterPack 里 `codesign -s -`），配合 `mac.identity: null`。
- **Windows 免安装包**：`scripts/pack-win.mjs` —— 直接下官方 electron win32 zip、
  塞 `resources/app`（不用 asar）、把 `electron.exe` 改名，zip 出去。**不需要 Wine**。
  带图标的正式安装包才需要 Windows 机器跑 `pnpm dist:win`。
- **自检**：`scripts/desktop-check.mjs` 用 `playwright-core` 的 `_electron.launch`，
  真起窗口 → 检查 http 源/预加载桥 → 导入 Word → 检查破图 → 开打印预览 → 截图。

踩过的坑（都是本机环境特有，记下来省时间）：
1. 本机 `ELECTRON_RUN_AS_NODE=1`，electron 会退化成普通 node（`--version` 打印 v22 而不是 v38），
   `require('electron')` 拿到的是二进制路径 → 必须 `env -u ELECTRON_RUN_AS_NODE`。
2. WorkBuddy 注入 `NODE_OPTIONS=--require node-language-shim.cjs`（FS broker），
   electron-builder 解压/删锁文件会被拒 → 打包命令要 `env -u NODE_OPTIONS` + 关沙箱。
3. `ELECTRON_BUILDER_CACHE` **不能放项目内**：缓存里的 `icon-tool.js` 会被 `"type":"module"`
   当 ESM 跑而报 `require is not defined`。放 `/tmp`。
4. electron 二进制下载要 `electron_config_cache`（不是 ELECTRON_CACHE），且 shim 下 mkdir 非递归，得先建好目录。
5. ESM 主进程里 `import { app } from 'electron'` 拿不到具名导出 → 主进程用 `.cjs`。
6. pnpm 12 不读 package.json 的 `pnpm.onlyBuiltDependencies`，要写 pnpm-workspace.yaml 的 `allowBuilds`。
