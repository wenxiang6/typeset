
## 多用户方案（2026-10-29 讨论）
- 用户明确：要的是「用户隔离」，不是多人协同编辑同一份稿。
- 定案：FastAPI 版多用户 = token 鉴权 + 数据全部挂 user_id，API 4 端点契约不变。
- 要点：users 表(token唯一)；docs/snapshots/templates 加 user_id（快照环形10按用户各算各的，templates 的 user_id 为 NULL 可作全局共享）；鉴权用 FastAPI dependency，token 无效 401；前端 serverSync.ts 封 authFetch 且 401 必须显式提示（不能沿用 mirrorPut 全静默）；推送工具改为 PUT /api/doc?push=1&u=<token>；老数据迁移给默认用户；首次带 ?u=<token> 的链接即邀请链接，token 存本地；本地主存+服务器镜像、降级、Electron 不联网等既有架构全部不变；并发 last-write-wins 不额外做。

## 凭证格式定稿（2026-10-29 深夜）
- 用户定案：凭证 = md5(name + ':' + secret)，不要裸 token。URL 格式 ?u=<name>&k=<md5>。
- skill 三处已改为 name+secret 模型：config.json users=[{name, secret}]；SKILL.md 多用户节写明 K=md5("<name>:<secret>") 带冒号拼接、推送带 &u=&k=、401 显式报错、viewerUrl 后端返回；run.sh 用 PAIBAN_USER/PAIBAN_SECRET 环境变量自动算 md5（macOS md5 -q / Linux md5sum 兼容，已用 python3 hashlib 对照验证一致）。
- FastAPI 版实现约定：users 表存 name+secret 原文（不存 md5 结果），验证时按 name 查 secret 重算比对；响应返回 viewerUrl。已向用户强调 md5 不提供安全性，secret 必须 openssl rand -hex 16。
